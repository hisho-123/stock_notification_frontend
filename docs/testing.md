# フロントエンドのカバレッジ

対象は複数ユーザー向けの登録・ログイン・一覧・通知設定の4画面。実Go API・DB・FMP・LINEは専用APIスタブによる自動テストに含めない。登録URLの状態、公開API、成否不明時のID照合、初回セッション復元との競合、ユーザー切替時の本文読込中の旧401と未完了要求の破棄も検証する。実行方法とレポートの場所は[README](../README.md#検証)を参照。

C0＝Istanbul Statements、C1＝Branches。Vitestは本番src全体でファイル別100%を必須とし、Playwrightは主要操作の100%を改善目標とする。両者は別々の実行結果であり合算しない。計測対象の分母はそれぞれの変換・計測結果に基づく。

## 確認した操作

- 登録URLの欠落・形式不正・確認中・確認失敗・410・409・429・有効期限、公開APIのCSRF除外、登録中の二重送信抑止。
- 登録成功時の空一覧・初期設定・Cookieセッション置換、成否不明時のlogin_id照合と再送停止、離脱中の結果破棄。旧ユーザー認証済みの成否不明ではクライアント認証だけ破棄し、サーバーセッションを失効させず新IDのログインへ進む。
- 初回セッション確認との並行、ユーザー切替後の旧応答と本文読込中の旧401の排除、取消後の再取得抑止。

- ログインの入力境界・認証失敗・試行制限・期限切れ・ログアウト失敗と再試行。
- 銘柄の正規化・登録・検索・全ソート・停止／再開・削除、空一覧と再取得失敗。
- 通知率の追加・削除・保存、取得／保存失敗、未保存の離脱・取消・破棄。
- Cookie・Origin・CSRF、401・403・404・409・422・429・502・503・504、通信断・不正JSON・成否不明。
- 再読み込み・履歴・Esc・フォーカス・IME、処理中の重複送信抑止、画面全体の横はみ出し。

## E2Eの未到達箇所

正確なファイル・行・分岐番号は、各実行で生成する`coverage/e2e/combined/priority/uncovered.md`に出力する。以下は初回計測で残った経路の理由。すべてVitestでは検証済みであり、E2Eの母数から除外しない。

| 対象                                                   | E2Eで未到達となる理由                                                                                             | Vitestでの確認                                                         |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| APIの一般例外メッセージ                                | APIクライアントは通常の通信失敗をApiErrorへ正規化するため、一般例外のフォールバックは通常操作から到達しない       | 一般例外を受けた画面の安全なエラー表示                                 |
| 認証の取消済み要求・Provider破棄・Provider未設定       | 本番のSPA内の移動では認証Providerを破棄しない。ページ全体の破棄後はJS実行環境も失われる。Provider未設定は構成ミス | 取消後の成功／失敗を無視、アンマウント時の後処理、Provider外利用の例外 |
| ダイアログのbusy既定値                                 | 現行の画面は常にbusyを明示する。省略時の共通部品契約は部品テストで確認する                                        | busy省略時の確定・Esc・フォーカス復帰                                  |
| 対象なしの削除・閉じた確認の確定                       | 非表示ダイアログはユーザーが操作できない                                                                          | 古い／非表示確認イベントでAPI送信・遷移を起こさない                    |
| ログインの処理中再送・一般例外                         | 通常の送信ボタンは処理中無効。ログインAPIは異常をApiErrorに正規化する                                             | フォーム再送抑止と、一般例外時のパスワード消去                         |
| 設定のロック中追加・遷移保留中の保存・取消後の成功応答 | ロック中の入力と、モーダル背面の保存は通常操作できない。取消済みfetchの成功応答も通常は到着しない                 | フォーム送信の抑止、保存完了で保留解除、取消済みの成功／失敗を無視     |
| 古い一覧成功応答の破棄                                 | ブラウザのfetchはAbortSignalで取消済みの応答を返さない。競合の防御経路は応答順序を制御して確認する                | 新しい結果が古い成功・失敗応答で上書きされない                         |

計測のために非表示のハンドラーをE2Eから直接呼んだり、カウンタを書き換えたりしない。画面・通信の正しい結果をアサートし、到達できない防御経路は上記の理由を残す。

## 計測基盤の確認

`npm run test:coverage-tools`は、文書の重複加算防止、欠落データの拒否、未importファイルの0%計上、HTML／JSON／LCOV／未到達位置の出力、本番成果物への計測コード混入拒否を確認する。

Vitestの閾値が実際に機能することは、入力テストだけに限定した`npm run test:coverage -- src/validation.test.ts`が未実行ファイルの0%を報告して終了1になることで確認した。その後、全テストを再実行して100%の成果物へ戻す。

受付がdisabledボタンに限られる重複した状態ガードと、全呼出元が指定するprivateメソッドの既定引数は整理した。フォーム送信・対象消失など、別の入口や遅延イベントに備える防御処理は維持する。通信遅延中の追加・行操作・保存が各1回だけ送信されることを単体・実ブラウザで確認する。
